#### 1. [Aurora RDS의 경쟁 상태(race condition) 발견 사례](https://news.hada.io/topic?id=24384)
**출처:** geeknews | **날짜:** 2025-11-15

Hightouch가 AWS Aurora RDS의 failover 과정에서 발생하는 race condition을 실험적으로 증명하고 AWS로부터 공식 확인을 받은 사례입니다. 개발자들은 클라우드 서비스의 알려지지 않은 버그를 체계적으로 발견하고 검증하는 방법을 배울 수 있습니다. 분산 시스템에서의 장애 처리와 경쟁 상태 디버깅에 대한 실무적인 인사이트를 제공합니다.

**핵심 포인트:**
- 클라우드 서비스에서 간헐적으로 발생하는 문제는 체계적인 실험과 로그 분석을 통해 재현 가능한 버그로 증명할 수 있다
- Aurora와 같은 관리형 데이터베이스의 failover 메커니즘에서도 race condition이 발생할 수 있으므로 애플리케이션 레벨에서 적절한 재시도 로직과 모니터링을 구현해야 한다
- 벤더와의 효과적인 소통을 위해서는 재현 가능한 테스트 케이스와 상세한 로그 증거를 준비하여 기술적 근거를 명확히 제시해야 한다

#### 2. [650GB 데이터(S3의 Delta Lake). Polars vs. DuckDB vs. Daft vs. Spark](https://news.hada.io/topic?id=24380)
**출처:** geeknews | **날짜:** 2025-11-15

개발자들은 650GB 규모의 S3 Delta Lake 데이터를 단일 노드(32GB 메모리)에서 처리할 때 Polars, DuckDB, Daft, Spark의 실제 성능 차이를 학습할 수 있습니다. 대용량 데이터 처리 시 각 엔진의 메모리 효율성과 처리 속도를 비교하여 프로젝트에 적합한 도구를 선택하는 기준을 얻을 수 있습니다.

**핵심 포인트:**
- 단일 노드 환경에서 대용량 데이터 처리 시 Spark 클러스터 대신 경량화된 엔진(Polars, DuckDB, Daft) 사용을 고려하여 인프라 비용을 절감할 수 있습니다
- 32GB 메모리 제약 하에서 각 엔진의 out-of-memory 처리 방식과 성능을 이해하여 하드웨어 스펙 계획 시 참고할 수 있습니다
- S3와 Delta Lake 조합에서 각 엔진별 I/O 최적화 방식을 파악하여 클라우드 환경에서의 데이터 파이프라인 설계에 활용할 수 있습니다

#### 3. [Continuous profiling for native code: Understanding the what, why, and how](https://grafana.com/blog/2025/11/14/continuous-profiling-for-native-code-understanding-the-what-why-and-how/)
**출처:** grafana | **날짜:** 2025-11-14

이 기사는 네이티브 코드를 위한 연속 프로파일링의 개념과 필요성, 그리고 구현 방법을 설명합니다. 개발자들은 로그, 메트릭, 트레이싱에 이어 네 번째 관찰성 기둥으로 부상한 프로파일링을 통해 애플리케이션 성능을 심층 분석하는 방법을 학습할 수 있습니다. 특히 프로덕션 환경에서 CPU, 메모리 사용량을 실시간으로 모니터링하여 성능 병목점을 식별하고 최적화하는 실무적 기법을 익힐 수 있습니다.

**핵심 포인트:**
- 프로덕션 환경에서 연속 프로파일링을 도입하여 실시간으로 CPU 사용률과 메모리 할당 패턴을 모니터링하고 성능 이슈를 조기에 발견할 수 있도록 구현하기
- 기존 관찰성 스택(로그, 메트릭, 트레이싱)에 프로파일링을 통합하여 성능 문제의 근본 원인을 코드 레벨에서 정확히 식별하는 체계 구축하기
- 네이티브 코드 프로파일링 도구를 활용하여 함수별 실행 시간과 호출 빈도를 분석하고, 핫스팟을 찾아 코드 최적화 우선순위를 결정하기

#### 4. [OpenTelemetry eBPF Instrumentation Marks the First Release](https://opentelemetry.io/blog/2025/obi-announcing-first-release/)
**출처:** opentelemetry | **날짜:** 2025-11-03

Grafana Labs, Splunk, Coralogix, Odigos 등 주요 기업들과 커뮤니티의 협력으로 OpenTelemetry eBPF Instrumentation의 첫 번째 알파 릴리스가 발표되었습니다. 이 도구는 애플리케이션 코드 수정 없이 자동으로 텔레메트리 데이터를 수집할 수 있는 혁신적인 관찰가능성 솔루션을 제공합니다. 개발자들은 기존 애플리케이션에 최소한의 침입으로 성능 모니터링과 분산 추적을 구현할 수 있게 되었습니다.

**핵심 포인트:**
- 기존 애플리케이션 코드를 수정하지 않고도 자동으로 메트릭, 로그, 트레이스 데이터를 수집할 수 있는 eBPF 기반 계측 도구를 활용하세요
- 프로덕션 환경에서 성능 오버헤드 없이 실시간 애플리케이션 관찰가능성을 구현하기 위해 OpenTelemetry eBPF를 테스트해보세요
- 다양한 프로그래밍 언어와 프레임워크에서 일관된 관찰가능성 데이터 수집을 위해 표준화된 OpenTelemetry 스펙을 적용하세요
