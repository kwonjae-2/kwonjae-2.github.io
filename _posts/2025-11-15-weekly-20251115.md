## 한국어 (Korean)

이번 주에도 찾아주셔서 감사합니다! SRE, Observability, 그리고 Infrastructure Engineering 분야의 가장 가치있는 아티클들을 소개합니다.

### 📚 이번 주 추천 아티클

#### 1. [Continuous profiling for native code: Understanding the what, why, and how](https://grafana.com/blog/2025/11/14/continuous-profiling-for-native-code-understanding-the-what-why-and-how/)
**출처:** grafana | **날짜:** 2025-11-14

네이티브 코드의 지속적 프로파일링은 로그, 메트릭, 트레이싱과 함께 현대 관찰 가능성의 네 번째 핵심 요소로 자리 잡고 있습니다. 이 기술은 애플리케이션의 성능 병목 지점과 리소스 사용 패턴을 실시간으로 분석하여 운영 효율성을 크게 향상시킵니다. 특히 네이티브 코드 환경에서 CPU, 메모리 사용량을 세밀하게 모니터링하여 성능 최적화와 비용 절감을 동시에 달성할 수 있습니다.

**핵심 포인트:**
- 네이티브 코드 환경에서 지속적 프로파일링 도구를 구현하여 실시간 성능 모니터링 체계를 구축하고 애플리케이션 병목 지점을 즉시 식별할 수 있도록 설정
- CPU, 메모리, I/O 등 핵심 리소스 사용 패턴을 프로파일링 데이터를 통해 분석하여 성능 최적화 우선순위를 결정하고 구체적인 개선 계획 수립
- 프로파일링 결과를 기존 관찰 가능성 스택(로그, 메트릭, 트레이싱)과 통합하여 포괄적인 성능 진단 및 문제 해결 워크플로우 구축

#### 2. [Demystifying Automatic Instrumentation: How the Magic Actually Works](https://opentelemetry.io/blog/2025/demystifying-auto-instrumentation/)
**출처:** opentelemetry | **날짜:** 2025-10-20

OpenTelemetry와 eBPF가 널리 사용되고 있음에도 불구하고, 대부분의 개발자들은 자동 계측(automatic instrumentation)이 실제로 어떻게 동작하는지 내부 메커니즘을 이해하지 못하고 있습니다. 이 글은 직접 구현을 권장하기 위함이 아니라, 개발자들이 자동 계측의 '마법' 같은 기능이 실제로 어떤 원리로 작동하는지 명확히 이해할 수 있도록 상세히 설명합니다.

**핵심 포인트:**
- OpenTelemetry의 자동 계측 메커니즘과 내부 동작 원리를 상세히 분석하여 개발자의 이해도를 높입니다
- eBPF와 같은 현대적 관측 기술의 실제 구현 방식과 작동 과정을 구체적으로 설명합니다
- 자동 계측 도구의 '블랙박스'적 특성을 해소하고 투명한 이해를 통해 더 나은 관측성 전략을 수립할 수 있도록 지원합니다

#### 3. [Understand, diagnose, and optimize SQL queries: Introducing Grafana Cloud Database Observability](https://grafana.com/blog/2025/11/13/understand-diagnose-and-optimize-sql-queries-introducing-grafana-cloud-database-observability/)
**출처:** grafana | **날짜:** 2025-11-13

Grafana가 데이터베이스 성능 문제 해결을 위한 새로운 클라우드 기반 관찰가능성 솔루션을 출시했습니다. 대부분의 애플리케이션 성능 문제가 데이터베이스에서 발생한다는 점에 주목하여, SQL 쿼리의 이해, 진단, 최적화를 지원하는 통합 플랫폼을 제공합니다. 이를 통해 개발자와 DBA가 데이터베이스 성능을 효과적으로 모니터링하고 개선할 수 있습니다.

**핵심 포인트:**
- SQL 쿼리 성능을 실시간으로 모니터링하고 병목 지점을 식별할 수 있는 통합 대시보드 활용
- 느린 쿼리와 비효율적인 데이터베이스 작업을 자동으로 감지하고 최적화 권장사항 제공
- 기존 Grafana 생태계와의 완벽한 통합을 통해 애플리케이션과 데이터베이스 메트릭을 한 곳에서 관리

#### 4. [Grafana Mimir 3.0 release: performance improvements, a new query engine, and more](https://grafana.com/blog/2025/11/03/grafana-mimir-3-0-release-all-the-latest-updates/)
**출처:** grafana | **날짜:** 2025-11-03

Grafana Mimir 3.0은 Prometheus와 OpenTelemetry 메트릭의 장기 저장을 위한 오픈소스 시계열 데이터베이스의 최신 버전입니다. 이번 릴리스는 성능 개선, 새로운 쿼리 엔진 도입, 그리고 멀티 테넌트 환경에서의 수평적 확장성을 크게 향상시켰습니다. SRE 팀들이 대규모 메트릭 데이터를 더 효율적으로 처리하고 분석할 수 있는 핵심 기능들이 강화되었습니다.

**핵심 포인트:**
- 새로운 쿼리 엔진을 도입하여 대용량 메트릭 데이터 조회 성능을 크게 개선하고 복잡한 분석 쿼리의 실행 속도를 향상시키세요
- 수평적 확장성과 멀티 테넌트 지원 기능을 활용하여 조직 내 여러 팀의 메트릭 데이터를 효율적으로 분리하고 관리하세요
- Prometheus와 OpenTelemetry 메트릭의 장기 보존 기능을 통해 과거 데이터 분석과 트렌드 모니터링을 위한 데이터 기반 의사결정을 강화하세요

#### 5. [Performance testing best practices: How to prepare for peak demand with Grafana Cloud k6](https://grafana.com/blog/2025/11/12/performance-testing-best-practices-how-to-prepare-for-peak-demand-with-grafana-cloud-k6/)
**출처:** grafana | **날짜:** 2025-11-12

Grafana Cloud k6를 활용한 성능 테스트 모범 사례를 통해 블랙 프라이데이, 제품 출시, 대규모 세일과 같은 피크 수요 상황에서 소프트웨어와 인프라가 받는 극심한 부하에 대비하는 방법을 제시합니다. 조직이 높은 고객 활동 기간 동안에도 안정적인 서비스를 제공할 수 있도록 체계적인 성능 테스트 전략을 구축하는 것이 핵심입니다.

**핵심 포인트:**
- 피크 수요 상황 이전에 Grafana Cloud k6를 사용하여 사전 성능 테스트를 체계적으로 실시하여 시스템 한계점과 병목 구간을 미리 파악하고 대응 방안을 준비해야 합니다
- 블랙 프라이데이나 제품 출시와 같은 예측 가능한 트래픽 급증 이벤트에 대비하여 실제 사용자 행동 패턴을 반영한 현실적인 부하 테스트 시나리오를 설계하고 실행해야 합니다
- 성능 테스트 결과를 바탕으로 인프라 확장성과 소프트웨어 최적화를 사전에 진행하여 고객 활동이 집중되는 시기에도 안정적인 서비스 품질을 보장할 수 있는 운영 체계를 구축해야 합니다

Welcome to this week's edition! Here are the most valuable articles on SRE, Observability, and Infrastructure Engineering.

### 📚 This Week's Picks

#### 1. [Continuous profiling for native code: Understanding the what, why, and how](https://grafana.com/blog/2025/11/14/continuous-profiling-for-native-code-understanding-the-what-why-and-how/)
**Source:** grafana | **Date:** 2025-11-14

Continuous profiling for native code is emerging as the fourth pillar of observability alongside logs, metrics, and tracing in modern application deployment. This technology enables real-time analysis of application performance bottlenecks and resource usage patterns, significantly improving operational efficiency. It provides detailed monitoring of CPU and memory usage in native code environments, allowing organizations to achieve both performance optimization and cost reduction simultaneously.

**Key Points:**
- Implement continuous profiling tools in native code environments to establish real-time performance monitoring systems and enable immediate identification of application bottlenecks
- Analyze core resource usage patterns (CPU, memory, I/O) through profiling data to determine performance optimization priorities and develop concrete improvement plans
- Integrate profiling results with existing observability stack (logs, metrics, tracing) to build comprehensive performance diagnostics and troubleshooting workflows

#### 2. [Demystifying Automatic Instrumentation: How the Magic Actually Works](https://opentelemetry.io/blog/2025/demystifying-auto-instrumentation/)
**Source:** opentelemetry | **Date:** 2025-10-20

Despite the widespread adoption of OpenTelemetry and eBPF, most developers lack understanding of how automatic instrumentation actually works under the hood. This article breaks down the 'magical' mechanics of automatic instrumentation—not to encourage building your own solution, but to help developers gain a clear understanding of the underlying principles and mechanisms.

**Key Points:**
- Provides detailed analysis of OpenTelemetry's automatic instrumentation mechanisms and internal operations to enhance developer understanding
- Explains the actual implementation methods and operational processes of modern observability technologies like eBPF in concrete terms
- Eliminates the 'black box' nature of automatic instrumentation tools and enables better observability strategy development through transparent understanding

#### 3. [Understand, diagnose, and optimize SQL queries: Introducing Grafana Cloud Database Observability](https://grafana.com/blog/2025/11/13/understand-diagnose-and-optimize-sql-queries-introducing-grafana-cloud-database-observability/)
**Source:** grafana | **Date:** 2025-11-13

Grafana has launched a new cloud-based observability solution specifically designed to address database performance issues. Recognizing that most application performance problems originate from databases rather than applications themselves, it provides an integrated platform for understanding, diagnosing, and optimizing SQL queries. This enables developers and DBAs to effectively monitor and improve database performance.

**Key Points:**
- Utilize integrated dashboards to monitor SQL query performance in real-time and identify bottlenecks
- Automatically detect slow queries and inefficient database operations while providing optimization recommendations
- Leverage seamless integration with existing Grafana ecosystem to manage application and database metrics in one place

#### 4. [Grafana Mimir 3.0 release: performance improvements, a new query engine, and more](https://grafana.com/blog/2025/11/03/grafana-mimir-3-0-release-all-the-latest-updates/)
**Source:** grafana | **Date:** 2025-11-03

Grafana Mimir 3.0 is the latest version of an open source, horizontally scalable time series database designed for long-term storage of Prometheus and OpenTelemetry metrics. This release delivers significant performance improvements, introduces a new query engine, and enhances multi-tenant scalability capabilities. SRE teams can now process and analyze large-scale metric data more efficiently with these enhanced core features.

**Key Points:**
- Implement the new query engine to significantly improve performance for large-scale metric data queries and accelerate execution of complex analytical queries
- Leverage enhanced horizontal scalability and multi-tenant capabilities to efficiently isolate and manage metric data across multiple teams within your organization
- Utilize long-term storage capabilities for Prometheus and OpenTelemetry metrics to strengthen data-driven decision making through historical data analysis and trend monitoring

#### 5. [Performance testing best practices: How to prepare for peak demand with Grafana Cloud k6](https://grafana.com/blog/2025/11/12/performance-testing-best-practices-how-to-prepare-for-peak-demand-with-grafana-cloud-k6/)
**Source:** grafana | **Date:** 2025-11-12

This article presents performance testing best practices using Grafana Cloud k6 to prepare for peak demand scenarios like Black Friday, product launches, and major sales that put intense strain on software and infrastructure. The focus is on establishing systematic performance testing strategies to ensure organizations can maintain stable service delivery during periods of high customer activity.

**Key Points:**
- Conduct systematic pre-performance testing using Grafana Cloud k6 before peak demand periods to identify system limitations and bottlenecks, and prepare appropriate response measures
- Design and execute realistic load testing scenarios that reflect actual user behavior patterns in preparation for predictable traffic surge events like Black Friday or product launches
- Establish operational systems that ensure stable service quality during periods of concentrated customer activity by proactively implementing infrastructure scalability and software optimization based on performance testing results
