#### 1. [Continuous profiling for native code: Understanding the what, why, and how](https://grafana.com/blog/2025/11/14/continuous-profiling-for-native-code-understanding-the-what-why-and-how/)
**출처:** grafana | **날짜:** 2025-11-14

네이티브 코드를 위한 지속적 프로파일링은 로그, 메트릭, 트레이싱에 이어 네 번째 관찰 가능성 기둥으로 자리잡고 있습니다. 이 기술은 애플리케이션의 성능 병목 지점을 실시간으로 식별하고 최적화할 수 있도록 도와줍니다. 특히 네이티브 코드 환경에서 CPU 사용량, 메모리 할당, 함수 호출 패턴을 세밀하게 분석할 수 있습니다.

**핵심 포인트:**
- 프로덕션 환경에서 지속적으로 프로파일링을 수행하여 실제 워크로드 조건에서의 성능 이슈를 파악하고 해결할 수 있습니다
- 네이티브 코드의 함수별 CPU 사용률과 메모리 할당 패턴을 시각화하여 성능 최적화 대상을 정확히 식별할 수 있습니다
- 기존의 로그, 메트릭, 트레이싱과 연계하여 종합적인 관찰 가능성 전략을 수립하고 근본 원인 분석을 강화할 수 있습니다

#### 2. [Understand, diagnose, and optimize SQL queries: Introducing Grafana Cloud Database Observability](https://grafana.com/blog/2025/11/13/understand-diagnose-and-optimize-sql-queries-introducing-grafana-cloud-database-observability/)
**출처:** grafana | **날짜:** 2025-11-13

Grafana가 데이터베이스 성능 문제 해결을 위한 새로운 클라우드 기반 관찰가능성 솔루션을 출시했습니다. 대부분의 애플리케이션 성능 문제가 데이터베이스의 느리고 비효율적인 쿼리에서 발생한다는 점에 착안하여, SQL 쿼리를 이해하고 진단하며 최적화할 수 있는 포괄적인 도구를 제공합니다.

**핵심 포인트:**
- 데이터베이스 쿼리 성능을 실시간으로 모니터링하고 분석하여 병목 지점을 신속하게 식별할 수 있습니다
- SQL 쿼리 최적화를 위한 구체적인 권장사항과 진단 정보를 제공하여 데이터베이스 효율성을 향상시킬 수 있습니다
- Grafana Cloud 플랫폼과 통합되어 기존 모니터링 워크플로우에 seamless하게 연동할 수 있습니다

#### 3. [Performance testing best practices: How to prepare for peak demand with Grafana Cloud k6](https://grafana.com/blog/2025/11/12/performance-testing-best-practices-how-to-prepare-for-peak-demand-with-grafana-cloud-k6/)
**출처:** grafana | **날짜:** 2025-11-12

Grafana Cloud k6를 활용한 성능 테스트 모범 사례를 통해 블랙프라이데이나 제품 출시 같은 대규모 트래픽 상황에 대비하는 방법을 다룹니다. 높은 고객 활동 기간 동안 소프트웨어와 인프라에 가해지는 극심한 부하를 효과적으로 관리할 수 있는 실용적인 접근법을 제시합니다.

**핵심 포인트:**
- 대규모 트래픽 이벤트 이전에 시스템 부하 테스트를 통해 성능 한계점을 사전에 파악하고 대비책을 마련해야 합니다
- Grafana Cloud k6의 분산 부하 테스트 기능을 활용하여 실제 사용자 트래픽 패턴을 시뮬레이션하고 병목 지점을 식별해야 합니다
- 성능 테스트 결과를 바탕으로 인프라 확장 계획을 수립하고, 모니터링 대시보드를 통해 실시간 시스템 상태를 추적해야 합니다

#### 4. [OpenTelemetry eBPF Instrumentation Marks the First Release](https://opentelemetry.io/blog/2025/obi-announcing-first-release/)
**출처:** opentelemetry | **날짜:** 2025-11-03

Grafana Labs, Splunk, Coralogix, Odigos 등 여러 커뮤니티 멤버들의 협력으로 OpenTelemetry eBPF 인스트루멘테이션의 첫 번째 알파 릴리스가 발표되었습니다. 이 기술은 애플리케이션 코드 수정 없이도 자동으로 관찰 가능성 데이터를 수집할 수 있게 해줍니다. eBPF를 활용한 이 솔루션은 기존 인스트루멘테이션의 복잡성을 크게 줄여주는 혁신적인 접근 방식을 제공합니다.

**핵심 포인트:**
- 애플리케이션 코드 변경 없이 자동 인스트루멘테이션을 통해 관찰 가능성 데이터 수집이 가능하므로, 기존 시스템에 즉시 적용 검토
- 알파 릴리스이므로 프로덕션 환경보다는 개발/테스트 환경에서 먼저 eBPF 기반 모니터링 기능을 평가 및 테스트
- 주요 벤더들(Grafana, Splunk 등)의 협력으로 개발된 오픈소스 표준이므로, 향후 안정화된 버전 출시 시 도입 계획 수립

#### 5. [Grafana Mimir 3.0 release: performance improvements, a new query engine, and more](https://grafana.com/blog/2025/11/03/grafana-mimir-3-0-release-all-the-latest-updates/)
**출처:** grafana | **날짜:** 2025-11-03

Grafana Mimir 3.0이 출시되어 성능 개선, 새로운 쿼리 엔진, 그리고 다양한 기능 향상을 제공합니다. 이는 Prometheus와 OpenTelemetry 메트릭의 장기 저장을 위한 오픈소스 수평 확장 가능한 멀티 테넌트 시계열 데이터베이스입니다. 2022년 첫 출시 이후 지속적인 개발을 통해 더욱 강력한 관측성 솔루션으로 발전했습니다.

**핵심 포인트:**
- 새로운 쿼리 엔진 도입으로 메트릭 조회 성능과 효율성이 대폭 향상되었습니다
- 수평 확장성과 멀티 테넌트 지원을 통해 대규모 환경에서의 메트릭 저장 및 관리가 용이합니다
- Prometheus와 OpenTelemetry 메트릭 모두 지원하여 다양한 모니터링 스택과의 호환성을 제공합니다

#### 6. [Demystifying Automatic Instrumentation: How the Magic Actually Works](https://opentelemetry.io/blog/2025/demystifying-auto-instrumentation/)
**출처:** opentelemetry | **날짜:** 2025-10-20

OpenTelemetry와 eBPF 기술이 널리 사용되고 있음에도 불구하고, 대부분의 개발자들은 자동 계측(automatic instrumentation)이 내부적으로 어떻게 작동하는지 이해하지 못하고 있습니다. 이 글은 개발자가 직접 구축하도록 권장하는 것이 아니라, 자동 계측의 내부 동작 원리를 명확히 설명하여 개발자들의 이해를 돕는 것을 목표로 합니다.

**핵심 포인트:**
- OpenTelemetry 자동 계측의 내부 메커니즘과 동작 원리를 깊이 있게 이해하여 관찰 가능성 구현 시 더 나은 의사결정을 할 수 있습니다
- eBPF와 같은 최신 관찰 기술들이 어떻게 애플리케이션 코드 수정 없이 텔레메트리 데이터를 수집하는지 학습할 수 있습니다
- 자동 계측 도구들의 한계와 장점을 파악하여 수동 계측과의 적절한 조합을 통해 효과적인 모니터링 전략을 수립할 수 있습니다

#### 7. [The Declarative configuration journey: Why it took 5 years to ignore health check endpoints in tracing](https://opentelemetry.io/blog/2025/declarative-config/)
**출처:** opentelemetry | **날짜:** 2025-10-21

Java OpenTelemetry에서 헬스체크 엔드포인트의 스팬을 효율적으로 제거하는 기능은 수년간 가장 많이 요청된 기능 중 하나였습니다. 이 글은 선언적 구성을 통해 불필요한 추적 데이터를 필터링하는 기능을 구현하기까지 5년이라는 긴 시간이 걸린 기술적 여정과 그 과정에서 얻은 교훈을 다룹니다. 관찰가능성(Observability) 시스템에서 노이즈를 줄이고 의미 있는 데이터에 집중할 수 있는 방법을 제시합니다.

**핵심 포인트:**
- 선언적 구성을 통해 헬스체크와 같은 반복적인 엔드포인트의 스팬을 자동으로 필터링하여 추적 데이터의 노이즈를 크게 줄일 수 있습니다
- OpenTelemetry의 복잡한 아키텍처와 다양한 사용 사례를 고려한 범용적인 솔루션 개발에는 상당한 시간과 신중한 설계가 필요합니다
- 효과적인 관찰가능성을 위해서는 모든 데이터를 수집하는 것보다 의미 있는 데이터를 선별적으로 수집하는 전략이 더 중요합니다

#### 1. [Continuous profiling for native code: Understanding the what, why, and how](https://grafana.com/blog/2025/11/14/continuous-profiling-for-native-code-understanding-the-what-why-and-how/)
**Source:** grafana | **Date:** 2025-11-14

Continuous profiling for native code is emerging as the fourth pillar of observability alongside logs, metrics, and tracing. This technology helps identify and optimize application performance bottlenecks in real-time. It provides detailed analysis of CPU usage, memory allocation, and function call patterns specifically in native code environments.

**Key Points:**
- Implement continuous profiling in production environments to identify and resolve performance issues under real workload conditions
- Visualize function-level CPU usage and memory allocation patterns in native code to accurately identify optimization targets
- Integrate with existing logs, metrics, and tracing to establish comprehensive observability strategy and enhance root cause analysis

Recognizing that most application performance problems stem from slow and inefficient database queries rather than the application itself, it provides comprehensive tools to understand, diagnose, and optimize SQL queries.

**Key Points:**

#### 3. [Performance testing best practices: How to prepare for peak demand with Grafana Cloud k6](https://grafana.com/blog/2025/11/12/performance-testing-best-practices-how-to-prepare-for-peak-demand-with-grafana-cloud-k6/)
